# Основа — открытый математический практикум

Статический каталог задач на русском языке. Основной исходный код — **Python**, без сторонних Python-пакетов и Node-сборки. HTML создаётся до публикации; на GitHub Pages работает готовая статика. JavaScript нужен для фильтров, сохранения прогресса в браузере и рендеринга формул через KaTeX. Раскрытие решений работает через `<details>` даже без JS.

## Быстрый старт

Нужен Python 3.10 или новее:

```sh
python3 scripts/check.py
python3 -m http.server 8000 --directory dist
```

Команды выполняются из корня проекта. Можно запустить всё одной командой `python3 run.py`. Откройте http://localhost:8000. Остановить сервер: Ctrl+C. После изменения контента повторите `python3 build.py` и обновите страницу. Сборка заново создаёт только каталог `dist/`; не храните в нём исходники.

## Структура

```text
build.py                          # генератор HTML и проверка данных
run.py                            # сборка и локальный сервер одной командой
index.html                        # вход из корня в собранный сайт
content/
  site.json                       # название, автор, ссылки и уровни
  problem.schema.json             # JSON Schema для редактора
  problems/**/*.json              # одна задача — один файл; допустимы подпапки
templates/index.html              # общий шаблон страницы
assets/
  style.css                       # адаптивное оформление
  app.js                          # поиск, фильтры, KaTeX
public/materials/*.pdf            # публикуемые PDF
examples/problem.template.json    # образец новой задачи
scripts/
  check.py                        # сборка и проверки ссылок/структуры
  make_sample_pdf.py               # исходник авторского PDF-примера
.github/workflows/pages.yml        # сборка Python → GitHub Pages
dist/                             # результат, не хранится в Git
```

Для такого каталога JSON удобнее Markdown: он не требует парсера, однозначно задаёт все блоки карточки и легко проверяется Python. Текст хранится как обычные строки с LaTeX, а не произвольный HTML. При росте каталога можно перейти на Markdown с frontmatter, сохранив поля схемы и генерацию на Python. Тысячи карточек стоит разделить на статические страницы по темам, чтобы не загружать всё сразу.

## Добавление задачи

1. Скопируйте `examples/problem.template.json` в `content/problems/07-my-problem.json`.
2. Замените `id` на уникальный идентификатор латиницей. Он задаёт ссылку вида `#my-problem`.
3. Заполните условие, шаги решения, ответ, ошибки и теорию. Тема автоматически попадёт в фильтр; поиск учитывает название, тему, теги и условие. Допустимы подпапки по темам. Сохраняйте id существующей задачи: к нему привязан прогресс читателя.
4. Добавьте PDF в `public/materials/` и укажите относительный путь `materials/имя.pdf`. Для внешнего материала используйте HTTPS-ссылку. Если PDF ещё нет, оставьте `materials: []`.
5. Выполните `python3 scripts/check.py`.

`content/problem.schema.json` можно подключить к редактору для подсказок. Генератор выполняет собственную проверку обязательных полей, типов, идентификаторов и локальных ссылок без установки библиотеки JSON Schema. Сам JSON Schema — более строгий контракт, в частности он запрещает неизвестные поля.

### Поля карточки

| Поле | Значение |
| --- | --- |
| `schema_version` | `1`, версия формата |
| `id` | Уникальное имя, например `matrix-system` |
| `title`, `topic` | Название и основная тема |
| `level` | `basic`, `school`, `advanced`, `challenge` |
| `minutes` | Ориентировочное время собственной попытки |
| `tags` | Массив поисковых тегов |
| `statement` | Массив абзацев условия |
| `materials` | Массив объектов `{ "title": "PDF-разбор", "url": "materials/file.pdf" }` |
| `solution.steps` | Массив абзацев рассуждения |
| `solution.answer` | Ответ |
| `solution.python` | Необязательный код для локальной проверки |
| `mistakes` | Массив типичных ошибок |
| `theory` | Массив объектов с `title` и необязательным `url` |
| `source` | Источник, номер задачи, страница или отметка об авторском примере |

Полный копируемый пример находится в `examples/problem.template.json`. Массивы `materials`, `mistakes`, `theory`, `tags` могут быть пустыми.

Формулы: `$x^2$` внутри строки, `$$...$$` отдельным блоком. В JSON обратный слеш экранируется: `"$\\frac{1}{2}$"`. HTML в строках не исполняется. Код Python отображается внутри решения, не запускается в браузере; для тяжёлых вычислений можно подготовить локальный скрипт с NumPy/SymPy и записать ход вычислений и результат в карточку. Численная проверка не заменяет доказательство.

## Библиографический ориентир: сборник Антонова

PDF книги не включён в проект. Карточки каталога составляются самостоятельно; библиографическая ссылка на сборник не означает, что конкретное условие взято из него. Новые авторские задачи не должны копировать или близко перефразировать условия книги. Для такого примера можно указать в `source`: «Авторская задача; библиографический ориентир: Н. П. Антонов, “Сборник задач по элементарной математике” (1973). Условие составлено самостоятельно и не является цитатой или переработкой задачи из сборника». Не указывайте книгу источником конкретной задачи, если задача из неё не взята.

Если нужно разобрать задачу из книги, укажите точное издание, номер и страницу для библиографической идентификации. Не публикуйте скан, изображение страницы или воспроизведённое/перефразированное условие без необходимых прав; ссылка на доступный экземпляр сама по себе не означает разрешения на распространение. Предпочтительный формат открытого каталога — независимо составленные задачи и собственные решения. Встроенный небольшой PDF — авторский разбор первого уравнения на английском языке, генерируется `scripts/make_sample_pdf.py`.

## GitHub Pages

Workflow `pages.yml` собирает сайт, проверяет его, загружает `dist/` как Pages artifact и публикует его. Шаги соответствуют [документации GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

1. Отправьте файлы в репозиторий GitHub. Workflow настроен на текущую ветку `master`; если основная ветка другая, замените имя в `pages.yml`.
2. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
3. Сделайте push в `master` или запустите workflow вручную во вкладке Actions.

Ссылки на стили, JS и PDF относительные, поэтому сайт работает и по адресу `https://USERNAME.github.io/REPOSITORY/`. Python исполняется только при сборке. GitHub Pages не исполняет Python на сервере.

KaTeX загружается с CDN с закреплённой версией; конфигурация использует [официальное расширение auto-render](https://katex.org/docs/autorender.html). Без сети формулы остаются читаемым исходным LaTeX, а карточки и спойлеры доступны. Для работы полностью без CDN скачайте CSS, JS, auto-render и каталог шрифтов одной версии KaTeX в `assets/vendor/`, заменив ссылки шаблона.

Публикация в текущей сессии не выполнялась. Workflow сработает после отправки в GitHub и включения Pages.

## Как развивать базу за год

Это ориентир наполнения, а не гарантия готовности к конкретному экзамену: точную программу нужно сверить с требованиями выбранного университета.

| Период | Основной фокус |
| --- | --- |
| Месяцы 1–3 | Дроби, степени, уравнения, неравенства, функции |
| Месяцы 4–6 | Геометрия, тригонометрия, координаты и векторы; задачи вступительного экзамена |
| Месяцы 7–9 | Пределы, производные, интегралы; матрицы и системы |
| Месяцы 10–12 | Дискретная математика, вероятность, доказательства; повторение и пробные экзамены |

Для дальнейшего HPC особенно пригодятся линейная алгебра, анализ, численные методы и понимание погрешностей. Сложность `challenge` обозначает характер задачи; она не означает, что любую такую задачу надо решать до освоения базы.

## Проверки

`python3 scripts/check.py` проверяет данные, уникальность HTML-якорей, наличие локальных материалов, закрытые по умолчанию решения и отклонение опасных ссылок. `node --check assets/app.js` проверяет синтаксис необязательного JS, если Node установлен. Эти проверки не заменяют визуальный просмотр в браузере.

Автоматический запуск кода из карточек намеренно отсутствует. Произвольный контент не следует исполнять во время сборки.

## Настройки и прогресс

`content/site.json` задаёт название, автора, внешние ссылки и список уровней. Изменение `coffee_url` подключает выбранный автором сервис поддержки. Сейчас ссылка ведёт в Telegram.

В этом браузере сохраняются последняя карточка, отметки о решённых задачах, фильтры и раскрытые блоки. Данные хранятся в `localStorage` отдельно для каждого пути сайта. При блокировке хранилища приложение продолжает работать, но не сохраняет состояние после закрытия. Между устройствами синхронизации нет.

`node scripts/check-ui.cjs` проверяет восстановление прогресса и поведение при изменении каталога; Node нужен только для этой проверки, не для Python-сборки или запуска сайта.
